# Team workflows

One markdown file per end-to-end process, written in the designer's words
before it becomes a skill. Use this outline:

- Trigger: what starts the work (ticket type, request, event).
- Inputs: what must exist before starting.
- Steps: what the designer does today, including which tools.
- Outputs: files, Figma frames, ticket comments.
- Checks: how the designer knows it is done well.
- Variations: where designers currently differ and which version the team picked.

Start with the workflow the team runs most often.
